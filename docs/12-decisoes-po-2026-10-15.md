## 0. Política de custeio — plataformas gratuitas até o primeiro contrato

**Decisão:** durante todo o ciclo (até M4, 15/01/2027) o projeto roda **exclusivamente em plataformas e planos gratuitos**. Nenhum membro da equipe nem o PO paga por API, hospedagem, CI ou armazenamento. A migração para planos pagos acontece **depois do primeiro contrato** com uma clínica, com o orçamento saindo dele. A meta RNF06 ("≤ R$ 0,50 por consulta") passa a ser **R$ 0,00 no semestre**, e o `run_eval.py` continua calculando o *custo equivalente* por consulta para dimensionar o orçamento pós‑contrato.

| Necessidade | Plataforma gratuita no semestre | Limite relevante | Migração após o 1º contrato |
|---|---|---|---|
| LLM (chat, SOAP, recomendações) | Google AI Studio — Gemini 2.5 Flash, *free tier* | Cotas por minuto e por dia; sem SLA | Gemini pago (ou Vertex AI) com termos de **não uso dos dados para treinamento** |
| Transcrição de áudio (padrão) | Gemini áudio, mesma chave gratuita | Mesmas cotas; arquivos ≤ ~20 MB por chamada → manter chunks de 5 min (B30) | Idem acima |
| Transcrição alternativa | Groq — Whisper large‑v3, *free tier* | Minutos de áudio por dia limitados | Groq pago, se o eval mostrar WER melhor |
| Transcrição offline | Vosk local | — | — |
| Repositório, CI, issues, quadro | GitHub **público** (Actions ilimitado em repo público; branch protection liberada) | — | Organização GitHub (Team) quando houver contrato |
| Banco e backend | Docker local (PostgreSQL + Flask), no computador do dev e do médico do piloto | — | VPS ou Postgres gerenciado |
| Web app (`copmed-web`) | Vite local / Docker; se precisar de link público, Vercel Hobby | Uso não comercial | Vercel Pro ou mesma VPS |
| Áudios e casos de referência | Repositório (sem Git LFS), arquivos pequenos | ≤ 100 MB por arquivo, repo enxuto | Bucket de objetos |
| Prontuários | e‑SUS PEC em Docker (gratuito); Amplimed só com conta de teste cedida pelo PO | — | Conta Amplimed da clínica contratante |

**Regra inegociável que acompanha o free tier:** planos gratuitos de IA podem usar os dados enviados para melhorar os modelos. Isso é aceitável **somente porque nenhum dado real de paciente entra no sistema durante o semestre** (regra 1 do kickoff; piloto com consultas simuladas). Antes do primeiro uso com paciente real, obrigatoriamente: plano pago com cláusula de não treinamento, DPA assinado e RIPD (ver `docs/08`, seção 6). Essa condição vira item de bloqueio na Sprint 7 (B63, revisão de segurança).

**Chaves:** cada desenvolvedor usa a própria chave gratuita do AI Studio no ambiente local (`API/.env`, nunca commitada). O eval (S4–S6) e o piloto (S6) usam uma chave gratuita dedicada criada pelo PO e guardada em GitHub Secrets. Se a cota gratuita estourar no eval, a equipe reduz o conjunto de casos e registra o limite atingido no relatório — isso é dado útil para o orçamento.

## 2. Diretrizes de processo que passam a valer (não são decisões de produto)

1. **Toda issue em andamento tem dono.** Nenhuma issue das Sprints 2–7 tem *assignee* hoje. No planejamento de cada sprint, cada item recebe uma pessoa.
2. **PR fecha issue.** Descrição com `Closes #n`. Itens já mesclados e ainda abertos (B06, B19, B20, B24, B27, B67 e outros) são fechados pelo Scrum Master até 17/10 com link da PR.
3. **Uma PR, um item.** A PR #92 carrega B36 + B21 + testes de B22 + script de import de issues. Dividir.
4. **Sprint fecha antes da próxima abrir.** B08, B09 e B18 (Sprint 1) entram como primeiros itens da Sprint 2. Trabalho de S3 (B29, B30, B36, B37) só é mesclado depois disso.
5. **Pergunta de revisão sem resposta bloqueia.** A observação do Rafael na PR #91 (token de 15 min × consulta de 25 min) é um requisito: a gravação precisa sobreviver à renovação do token (B22 + B29).
6. **CI verde significa Actions verde**, não GitGuardian. Os três alertas do GitGuardian foram falsos positivos (senha fictícia em teste, `POSTGRES_PASSWORD=copmed` em exemplo); manter o GitGuardian ativo e responder cada alerta na própria PR, como o Gabriel fez na #89.
